# Модели и инварианты

## PitchPreset

`id`, `nameKey`, `outfieldPlayers`, `feeKgs`. Вместимость команды = `outfieldPlayers + 1`, игры = вместимость × 4. Начальные значения: `pitch1`, `pitch2` по шесть; `pitch3` пять. Названия и цена — настраиваемые демонстрационные значения.

## FootballGame

`id`, `pitch`, `startTime` (UTC), `bookings` (UID → Booking), `fromCache`. Игры автоматически получаются из расписания, а не создаются игроком. `freePlaces(team)` вычисляется из броней команды. `isPast(now)` истинно начиная точно с `startTime`.

## Booking

`userId` — ключ карты, `team` — red/blue/yellow/green, `places` — целое от 1 до вместимости, `bookerName` — непустое публичное имя до 80 символов, `friendNames` — список до N − 1 строк, каждая до 80 символов. Пустая строка сохраняет позицию неназванного друга. Остальные места также считаются гостями.

Один UID имеет одну бронь в игре. Вся группа находится в одной команде. При редактировании команды должны совпасть; место владельца всегда входит в `places`. Отмена освобождает все места брони.

`position` — пожелание владельца, `friendPositions` — пожелания друзей по индексу места, до N − 1. Допустимы `any`, `goalkeeper`, `defender`, `midfielder`, `forward`. Отсутствующие поля и индексы означают `any` («Без разницы»). Позиции видны в составе и не влияют на счётчики мест или возможность выбрать вратаря нескольким игрокам.

Необязательный список `rightPositions` хранит сторону по индексу участника (владелец — 0). Пропущенное значение означает левую точку для парной роли и центральную точку для одиночной. Максимальная длина равна числу мест в брони.

## Firestore

`footballBookings/{epochSeconds_pitchId}`:

```text
startTime: Timestamp
pitchId: "pitch1"
bookings: { uid: { team, places, bookerName, friendNames, position?, friendPositions?, rightPositions? } }
counts: { red: 0..capacity, blue: 0..capacity,
          yellow: 0..capacity, green: 0..capacity }
```

`counts` — проверяемая серверными правилами проекция, не отдельный источник истины. Каждый счётчик изменяется ровно на разницу старой/новой брони владельца запроса. Не добавлять hostId, paid, paymentStatus, scores или goalkeeperSlot.

Граничные случаи: N=0, N выше остатка, лишние имена, дублирующая бронь, смена команды без отмены, время ровно начала, одновременная запись на последний остаток. Всё это проверять независимо от кнопок UI.
